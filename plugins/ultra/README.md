# Ultra

Ultra 是 Coda 的会话策略插件。主 Agent 主动拆分可并行的工作，通过 Coda 子会话执行并整合结果；简单任务仍可直接完成。首版使用支持委派协议的 Codex 插件，宿主和 Codex 适配器须同时包含会话策略 v1 接口。旧宿主会拒绝 `sessionPolicies` 声明，不会把没有约束的提示词当作 Ultra 模式。

安装 `plugins/ultra` 后，在会话设置开启 **Ultra**。默认关闭；项目或本机的「默认开启 Ultra」可作为会话默认值，会话仍可覆盖。开关修改从下一轮生效。

在「设置 › 插件 › Ultra」配置偏好；项目插件设置可覆盖本机设置。

| 设置 | 行为 |
| --- | --- |
| 子 Agent 候选顺序 | 留空继承主 Agent 本轮实际 Agent、模型、推理等级与模型选项。用 `01`、`02` 等序号指定候选，采用首个可用且符合限制的配置 |
| 各模型的推理限制 | 键为 `agent\|model`，值为 `low,medium,high` 等允许集合，或 `<=high` 等上限。上限只使用模型明确报告的顺序 |
| 并发子 Agent 数 | 默认 3，主 Agent 不计入；还受 Coda 的总上限限制 |
| 候选都不可用时跟随主 Agent | 默认关闭。开启后，最后尝试父配置；仍须满足模型限制 |
| 允许 Agent 选择候选以外的模型 | 默认关闭。没有配置候选时，只允许父模型 |

不同模型使用各自的推理等级和默认值；不会将父模型的 `max` 套到其他模型。继承值超过上限时会调整并记录原因；Agent 显式请求越界则失败。目录缺少该模型的能力信息时拒绝选择，不借用别的模型信息。候选中的审批模式不用于提升权限，始终遵守 Coda 的委派规则。

子会话保存创建时的执行配置，修改父模型或候选优先级不改写已创建任务。通过 `send` 续跑时保留子会话配置，并检查适用的硬限制。请求重试、防重、并发计数、结果自动回传和停止归属都由 Coda 管理。子会话不再派生子会话；Ultra 开启时 Codex 原生委派工具关闭。

## 策略命令

`policy.mjs` 从标准输入读取一份 JSON，向标准输出写一份 JSON。失败时只向标准错误写原因并以非零状态退出。解析无副作用，不访问账号或模型服务。

输入 `version: 1`，`phase` 为 `turn`、`spawn` 或 `send`；`settings` 是已解析的插件设置，`parent` 是父轮次实际配置，`request` 是原始派生意图（续跑时是已有子会话的执行快照），`catalog` 提供每模型能力，`limits.maxChildren` 为宿主上限。

输出包括轮次指令、子会话指令、并发约束，以及派生时的 `target`、配置来源 `source` 和原因 `reasons`。宿主在开始任务前核对适配器实际值，解析器本身不启动任务。

验证：`node --test test/plugins/ultra/policy.test.mjs`。完整协议见仓库的 [Agent 接入协议](../../docs/agent-protocol.md)。
