# 实现与验证

按已选提案修改；review 返回时先读历史 findings。遵循已启用规范、项目构建入口和生成物规则。保持修复范围与观察到的问题对应。

通过 `vczh check <id> -- <命令> <参数...>` 执行项目必需验证，取得 ID。所有引用的检查必须正常结束、退出码为 0，且对应当前代码。代码再次变化时重跑相关检查；不要引用旧 ID。检查输出可能提交入库，避免命令打印凭据。

```json
{"summary":"最终实现、提案验证结果、测试边界与未覆盖风险","checks":["c-检查ID"]}
```

保存并 `vczh task record <id> --file <文件>`，再答复 workflow_task completed。核验关心实际结果而非“应该通过”。外部环境无法验证时明确受阻；不能伪造一个成功命令替代项目要求的检查。
